# IITC 插件：maxfield-planner

## 安装

桌面端请用装有 Tampermonkey 或 Violentmonkey 的浏览器打开：

https://raw.githubusercontent.com/LongHuamin/iitc-plugin-maxfield-planner/main/iitc-plugin-maxfield-planner.user.js

IITC Mobile 请把上面这个地址添加为插件。安装之后会自动更新。

在地图上直接点选 portal，或导入 IITC 导出的 bookmark JSON，再点「规划」，用 **Fan Fields 2 的原版规划算法**生成 field 最大化的 link、行走顺序和统计。不需要 Draw Tools 多边形。

当前版本：`1.3.8`

本插件是基于 [Fan Fields 2](https://github.com/Heistergand/fanfields2/) 的个人修改版，不是官方 Fan Fields 2。规划引擎在 ISC 许可下派生，版权声明保持原样：Copyright © 2018-2025 IITC plugin: Fan Fields 2，Copyright © 2018 Justus Kenklies。原版算法（凸包锚点 Cycle Start、顺/逆时针、Inbound/Outbound、候选排序、`getThirds2` 成场顺序、不交叉连线）按原文移植，界面则沿用本插件原来的边缘停靠面板。

兼容 **IITC 桌面端** 和 **IITC Mobile**。

## 使用方法

1. 安装并启用插件后，地图边缘会出现一个「规划」按钮（类似书签的边缘开关，默认在右侧）。可以按住拖动，松手后会吸附到最近的上、下、左或右边缘，位置会记住。默认不会自动弹出窗口。
2. 需要时点「规划」打开窗口；点窗口上的 × 会重新收起，回到边缘按钮。图层列表里的「Field 最大化规划」只控制规划线的显示/隐藏，不控制窗口。也可以在侧边工具栏点 **Field 规划**。
3. 窗口标题栏右侧有四个按钮，从左到右是：**中英文切换**（中文界面显示 `EN`，英文界面显示 `中`）、**深浅色主题切换**（深色主题显示「亮」，浅色主题显示「暗」）、折叠、关闭。语言和主题会记住，默认仍是中文、深色主题。
4. 桌面端窗口默认宽度 360px，高度随内容自适应（不超过可视区域）。可拖动左侧边缘调整宽度（约 280–720px，且不超过窗口的 90%），也可拖动下边缘或右下角调整高度；宽度和手动拉过的高度会记住。双击下边缘或右下角可恢复自适应高度。手机端仍左右贴边，不使用该像素宽度。
5. 在地图上直接点击 portal，名称会进入窗口列表。列表只显示约 3 行，可滚动。要从规划中排除或重新加入某个 portal，只能在窗口列表里点「移除」或「恢复」；点「移除」不会改变列表顺序。收集阶段再点已经在列表里的 portal，不会把它取消，只会提示已在列表中。
6. 也可以点 **导入**，选择从 IITC Bookmarks 导出的 JSON。成功后这些 portal 会成为当前选定列表，窗口上方会提示「已成功导入 N 个 portal，可执行规划」；失败则会说明原因。导入会替换当前已选 portal，并清除已有规划，需要再点一次「规划」。
7. 选够至少 3 个 portal 后，点 **规划**。地图上会画出 link、叠层 field（层数越深颜色越深），以及步行路线和站序编号。
8. 规划完成后，在地图上再点击已选 portal，窗口会滚动并高亮列表里的对应项，不会改变是否参与规划。当前锚点不能移除；要换锚点，请再点一次「规划」。在列表里点「移除」或「恢复」后，如果已经有规划，会立刻按剩下的点重新规划，地图上的线不会先消失再等你重点「规划」。

### 如何看到另外几种拉法

这和原版 Fan Fields 2 一样，不是再点一次「规划」去切换自制剖分。规划完成后，再点 **规划** 会按原版逻辑立刻切换到下一种方案（约 0.2 秒）：先在凸包顶点上循环锚点（Cycle Start），全部走完后再切换顺时针 / 逆时针。「规划」按钮会显示当前是第几种，例如 1/6、2/6。

旁边的 **Inbound / Outbound** 通常不会改变地图上的连线形状，只改变锚点那些星形 link 的投出方向：

- **Inbound**（默认）：把 link 投向锚点，所以锚点往往需要很多钥匙。
- **Outbound**：从锚点往外投。一个 portal 最多向外投 8 条，再多就要用 SBUL；这时会显示 SBUL 数量（0–4，默认 2），对应原版 `availableSBUL`，上限是 `8 + SBUL×8`。

默认与原版相同：顺时针、Inbound、SBUL = 2。Respect Intel 默认关闭，规划只根据所选点的几何，不要求地图上已有 Intel link，也不需要 Draw Tools。

### 颜色

在操作按钮上方可以分别给 Field、Link 和行走轨迹选颜色：点色块打开色板。色板按 Office / WPS 风格排列，包含「主题颜色」和「标准色」，也可以用系统取色器选任意颜色。选择会记住。默认 Field 为绿色 `#16d977`，Link 为红色 `#e53935`，行走轨迹为金色 `#ffd24a`。每个色块后面都有一个勾选框：Field、Link、轨迹分别控制地图上是否显示 field、link 和步行路线（折线、箭头和站序号）。默认全部勾选，选择会记住，重新规划后也保持。取消勾选只影响地图显示，规划结果、统计、导出和收藏都不受影响。

## 计算规则

规划算法来自 Fan Fields 2，而不是 0.9.x 里那套自制插入剖分：

- 把所选 portal 投影到 Web Mercator（缩放级别 16，与原版 `PROJECT_ZOOM` 相同），求凸包，用 `startingpointIndex` 在凸包顶点上选锚点。
- 按从锚点出发的方位角排序，在最大角缝处切开，再按顺时针或逆时针得到访问顺序（`sortedFanpoints`，第 0 个是起点 / 锚点）。
- 按访问顺序为每个新点收集 `pb < pa` 的候选：锚点（`pb === 0`）的度量是 `Infinity`，因此总是先考虑连向锚点的星形 link；其余候选按 `距离(新点, 候选) + 距离(锚点, 候选)` 从大到小排序。
- 与已接受的 link 或原版预生成的星形 `fanlinks` 相交的候选会被拒绝。共享端点不算交叉；共线（分母为 0）按原版视为相交。
- 成场来自 `getThirds2`：一条被接受的 link，与已经存在的公共邻点组成三角形。这就是 field 的生成顺序。
- 行走路线就是 `sortedFanpoints` 的访问顺序，不是另行计算的最短路。

### 统计

- **Portal**：当前参与规划的全部已选 portal 个数（含锚点）。
- **Link / Field**：规划生成的 link 数和三角形数。一个三角形外沿、内部点为 `i` 的满场扇形，通常是 `1 + 3i` 个 field、`3n - 6` 条 link（例如 41 个点、38 个内点时为 115 场、117 条）。
- **层数**：规划完成后再统计的最大叠层深度，不会改变原版生成了哪些三角形。
- **Build AP**（与原版一致）：`有效 link × 313 + 有效 field × 1250`。另外会按地图上的实时状态估算占领 / 插脚 AP（占领 625，每支谐振器 125），并单独标明，不会替换官方的 link+field AP。
- 若某条 link 需要从已经盖住的 field 下方投出、且长度超过 2 公里，原版会把它标为无效（图上用虚线），并从有效计数和 Build AP 中排除，但不会从规划里删掉这条线。若有效数与总数不同，窗口会说明。

### 连接顺序

- 按行走站序排列，起点会标成「起点 / START」。
- 成场的投出写为 `portal A——>portal B  +N 场`。
- 钥匙明细写为 `名称：需要数`。若已安装 IITC 的 [Keys](https://iitc.app/) 或 Live Inventory 插件，会改成 `名称：20（5）` 这种格式：前面是本规划需要的钥匙数，括号里是你当前库存。库存不足时该行会标红。钥匙在 Ingress 里不会因投出而消耗。
- 在「连接顺序」或列表里点击 portal 名称，地图会平移并选中该 portal，不改变当前缩放，也不会改动规划。

## 安装

插件文件：`iitc-plugin-maxfield-planner.user.js`（当前版本 1.3.8）。推荐用文首的地址安装，以便自动更新。

### 桌面端（IITC-CE 或 Tampermonkey）

1. 安装 [IITC-CE](https://iitc.app/) 或 Tampermonkey / Violentmonkey。
2. 打开文首的安装地址，或打开本地的 `iitc-plugin-maxfield-planner.user.js`。如果以前装过 0.9.x、1.0.0、1.1.0、1.2.x 或 1.3.x，请用这个 1.3.8 覆盖安装。
3. 打开 Ingress Intel 地图，确认插件已启用。

### IITC Mobile

1. 在插件管理中添加文首的地址并启用，或把 `iitc-plugin-maxfield-planner.user.js` 拷到手机后导入并启用。
2. 打开 Intel 地图后即可使用。手机上可以把窗口折叠（标题栏的「–」），或先关掉窗口、只留边缘按钮。窗口贴边隐藏时，点击地图上的 portal 不会自动弹出窗口；要点选采集，请先打开窗口。未加载的 portal 无法采集。

### 收藏与当前规划同步（GitHub Gist）

收藏，以及当前正在编辑的规划，都可以用你自己的 GitHub Gist 在电脑和 IITC Mobile 之间同步。当前规划不用先存成收藏。不设置也能照常使用，数据仍保存在本机。

1. 创建 token（二选一）：
   - 经典 token：GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token (classic)，只勾选 `gist`。
   - 细粒度 token：同一页面选 Fine-grained tokens → Generate new token，在 Account permissions 里把 Gists 设为 Read and write。
2. 在插件窗口「收藏」那一行点 **设置**，把 token 粘贴到 `GitHub token` 框里，点 **保存**。Gist ID 可以留空，插件会自动找到或新建一个私密 Gist。收藏在 `maxfield-planner-favorites.json`，当前规划在 `maxfield-planner-current.json`（已选 portal、排除的 portal，以及顺/逆时针、Inbound/Outbound、SBUL 和锚点）。
3. 电脑和手机各粘贴一次同一个 token。
4. 每次启动会自动拉取收藏和当前规划。收藏在保存或删除后自动上传。当前规划在增删 portal、导入、重新规划、切换方案、改设置或清空之后自动上传。点 **同步** 会同时同步这两样。较新的一份会留下，不会用旧的盖掉新的。

token 只保存在本机浏览器里，不会写进 Gist 或日志。要停用同步，点 **设置** → **清除**。token 过期后会提示「同步失败：token 无效或已过期」，重新创建一个粘贴即可。

本插件的自动更新指向本仓库，没有指向 Fan Fields 2 官方仓库，不会被官方插件覆盖，也不会去覆盖官方 Fan Fields 2。

## 开发与测试

规划引擎在 `engine/fanfields2-engine.js`，可在 Node 中运行（`engine/geo.js` 提供与 Leaflet 一致的 Web Mercator 投影，缩放级别 16）。界面在 `src/plugin-ui.js`。原版参考源码在 `vendor/fanfields2/`。

```bash
node test/test-engine.js
node test/test-fav-sync.js
node test/test-current-sync.js
node build.js
```

`testdata/buxingjie-41.json` 是 41 个 portal 的「步行街多重」书签。凸包三个顶点是祿位高增、地王石柱、亨氏豪庭里的健身器材。循环这三个锚点，应得到三种不同的满场扇形：各 115 个 field、117 条 link，锚点度数为 40。

### 1.0.0

这是一次基于 Fan Fields 2 原版算法的重写，**不是**对 0.9.3 自制规划器的修补。

0.9.x 自己实现了一套插入剖分 / 扇形扫描，同一组点往往只给出一种连线，和 Fan Fields 2 用 Cycle Start 在凸包锚点上切出的 3–4 种满场方案对不上。1.0.0 改为在原版 `updateLayer` 逻辑上做独立界面：点选 portal 后规划，用「上一个 / 下一个锚点」、顺/逆时针、Inbound/Outbound 切换方案。已去掉「底边规划」和「三点定场」这两种旧规划模式。
